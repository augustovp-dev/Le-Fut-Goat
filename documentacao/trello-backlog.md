## Estrutura Recomendada do Quadro

### 1. Backlog

Cards que representam ideias ou melhorias futuras.

- Salvar carta do jogador no banco
- Criar ranking de overalls
- Criar página de perfil
- Adicionar histórico de cartas
- Melhorar responsividade mobile
- Criptografar senha do usuário
- Criar logout com confirmação
- Exibir nome do usuário na dashboard

### 2. A Fazer

Cards que devem ser feitos antes da entrega.

- Revisar navegação entre páginas
- Testar cadastro
- Testar login
- Testar dashboard
- Revisar textos da apresentação
- Conferir script do banco
- Conferir imagens e vídeo
- Preparar apresentação final

### 3. Em Desenvolvimento

Cards que estão sendo feitos no momento.

- Ajustar documentação
- Montar slides
- Organizar roteiro de fala

### 4. Validação

Cards prontos para teste.

- Cadastro criando usuário no banco
- Login gravando sessão no navegador
- Menu mudando após login
- Dashboard calculando overall
- Gráfico radar carregando
- Página de história abrindo corretamente

### 5. Concluído

Cards finalizados.

- Estrutura inicial do projeto
- Página inicial
- Página de história
- Tela de cadastro
- Tela de login
- Dashboard de atributos
- Organização das rotas de usuário
- Conexão com banco de dados

## Cards Detalhados

### Card: Página Inicial

Lista: Concluído

Descrição:

Criar a home do projeto com vídeo de fundo, apresentação do tema e cards sobre futebol.

Checklist:

- Header com navegação
- Vídeo de fundo
- Cards informativos
- Chamada para cadastro
- Rodapé

### Card: Página Minha História

Lista: Concluído

Descrição:

Criar uma página com a trajetória pessoal no futebol, principais momentos, desafios e aprendizados.

Checklist:

- Texto dividido em seções
- Galeria de imagens
- Lista de destaques
- Rodapé

### Card: Cadastro

Lista: Validação

Descrição:

Permitir que o usuário crie uma conta usando nome, email e senha.

Checklist:

- Validar campos vazios
- Validar email
- Validar senha
- Enviar dados para o back-end
- Mostrar mensagem de sucesso ou erro

### Card: Login

Lista: Validação

Descrição:

Permitir que o usuário entre no sistema com email e senha.

Checklist:

- Validar campos vazios
- Consultar usuário no banco
- Salvar dados no sessionStorage
- Redirecionar para a home
- Mostrar erro quando o login falhar

### Card: Dashboard

Lista: Validação

Descrição:

Permitir que o usuário informe atributos de jogador e receba uma análise visual.

Checklist:

- Receber atributos de 0 a 100
- Calcular overall
- Definir posição ideal
- Criar cards de KPI
- Criar barras de desempenho
- Exibir gráfico radar

### Card: Banco de Dados

Lista: A Fazer

Descrição:

Conferir se o script do banco está alinhado com as tabelas usadas no back-end.

Checklist:

- Criar banco
- Criar tabela de usuários
- Testar cadastro
- Testar login

### Card: Apresentação

Lista: Em Desenvolvimento

Descrição:

Preparar uma apresentação curta, objetiva e com foco no problema, solução, funcionalidades e aprendizados.

Checklist:

- Slide de capa
- Slide de objetivo
- Slide de tecnologias
- Slide de arquitetura
- Slide de páginas
- Slide da dashboard
- Slide do banco
- Slide de aprendizados
- Slide de próximos passos
- Treinar fala

## Roteiro de Uso do Trello na Apresentação

Durante a apresentação, mostre o quadro rapidamente e explique:

- O Backlog guarda ideias futuras.
- A lista A Fazer representa pendências finais.
- Em Desenvolvimento mostra o que está sendo ajustado agora.
- Validação mostra o que precisa ser testado.
- Concluído mostra o que já foi entregue.

Fala sugerida:

```text
Usei o Trello para organizar o projeto por etapas. Separei as tarefas em backlog, pendências, desenvolvimento, validação e concluído. Isso me ajudou a acompanhar o que já estava pronto e o que ainda precisava ser testado antes da apresentação.
```
